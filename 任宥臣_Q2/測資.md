## Problem 2：教室預約排程管理系統

### 測試一：教室新增與基本驗證

1. 新增教室名稱「電腦教室 A」，確認產生教室編號 `1`。
2. 新增教室名稱「電腦教室 B」，確認產生教室編號 `2`。
3. 再次新增「電腦教室 A」，應拒絕新增並提示名稱重複。
4. 新增空白教室名稱，應拒絕新增。
5. 選取教室編號 `1`，修改名稱為「電腦教室一」，確認編號仍為 `1`。
6. 選取教室編號 `2`，嘗試修改名稱為「電腦教室一」，應拒絕修改並保留原名稱。
7. 未選取教室就按「修改」或「刪除」，應顯示提示訊息。

### 測試二：預約新增與時間衝突

在已建立的兩間教室中，依序新增以下預約：

| 預約 | 教室 | 預約人 | 開始 | 結束 | 預期結果 |
|---:|---|---|---|---|---|
| 1 | 電腦教室一 | 王小明 | 09:00 | 10:00 | 成功，產生預約編號 `1` |
| 2 | 電腦教室一 | 李小華 | 10:00 | 11:00 | 成功，首尾相接不算衝突 |
| 3 | 電腦教室 B | 陳大文 | 09:00 | 10:00 | 成功，不同教室不衝突 |
| 4 | 電腦教室一 | 林小美 | 09:30 | 10:30 | 拒絕，與預約 `1` 衝突 |

預約 `4` 新增失敗後，預約列表不得出現該筆資料，下一筆成功新增的預約仍應使用編號 `4`。

### 測試三：預約欄位與時間驗證

以下資料皆應拒絕新增，且不得寫入預約列表：

| 測試內容 | 測試值 | 預期結果 |
|---|---|---|
| 預約人空白 | `   ` | 顯示錯誤 |
| 未選擇教室 | 空白 | 顯示錯誤 |
| 時間格式錯誤 | `9:00` | 顯示錯誤，要求 `HH:mm` |
| 結束等於開始 | `10:00`～`10:00` | 顯示錯誤 |
| 結束早於開始 | `11:00`～`10:00` | 顯示錯誤 |
| 跨日預約 | `23:00`～`01:00` | 顯示錯誤 |
| 時間超出範圍 | `24:00`～`25:00` | 顯示錯誤 |

### 測試四：排序、修改與刪除

1. 新增教室一的預約 `08:00`～`08:30`，確認預約編號為 `4`。
2. 確認排程依「教室編號、開始時間、預約編號」排序，順序應為：

   ```text
   教室一 08:00～08:30（預約 4）
   教室一 09:00～10:00（預約 1）
   教室一 10:00～11:00（預約 2）
   教室 B 09:00～10:00（預約 3）
   ```

3. 選取預約 `2`，修改結束時間為 `12:00`，確認預約編號仍為 `2`。
4. 嘗試將預約 `1` 修改為 `10:30`～`11:30`，應拒絕修改，且原本的 `09:00`～`10:00` 資料保持不變。
5. 將預約 `1` 修改為原本的 `09:00`～`10:00`，應允許通過；修改時不得與自己發生衝突。
6. 刪除預約 `4`，再於電腦教室一新增 `13:00`～`14:00` 的預約，確認新編號為 `5`，不得重新使用 `4`。
7. 未選取預約就按「修改」或「刪除」，應顯示提示訊息。

### 測試五：教室刪除限制與編號

1. 嘗試刪除仍有預約的教室一，應拒絕刪除。
2. 嘗試刪除仍有預約的教室 B，應拒絕刪除。
3. 新增「視聽教室」，確認編號為 `3`。
4. 刪除沒有預約的視聽教室，應成功。
5. 再新增「會議室」，確認編號為 `4`，不得重新使用已刪除的 `3`。

### 測試六：清除與資料保留

1. 選取教室或預約資料，按下「清除」。
2. 確認只清空輸入欄位與選取狀態，不刪除既有教室或預約。
3. 新增或修改發生錯誤時，確認原本資料仍然保留。
4. 關閉程式再重新開啟後，確認是否依題目規定重新開始；本題不要求資料持久化。

## Problem 3：系統日誌分析器

測試檔案如下：

| 檔案 | 測試目的 |
|---|---|
| `in-1.log` | 全部有效資料、各等級統計與關鍵字搜尋 |
| `in-2.log` | 空白行、欄位數錯誤與不合法等級 |
| `in-3.log` | 空檔案邊界案例 |
| `in-4.log` | 查無關鍵字案例 |
| `in-5.txt` | `.txt` 副檔名與正常資料處理 |

### 測試步驟一：正常資料與關鍵字搜尋

1. 按下「開啟檔案」，選取 `in-1.log`。
2. 確認同一個 `RichTextBox` 先顯示完整原始日誌內容。
3. 在關鍵字欄輸入 `CACHE`，按下「分析／搜尋」。
4. 確認同一個 `RichTextBox` 改為顯示符合關鍵字的日誌列表。
5. 確認統計結果如下：

   ```text
   TOTAL 10
   VALID 10
   INVALID 0
   INFO 4
   WARN 3
   ERROR 3
   MATCHED 2
   ```

6. 確認搜尋結果共有 2 筆，且大小寫不同仍可搜尋成功。

### 測試步驟二：格式錯誤資料

1. 開啟 `in-2.log`。
2. 輸入關鍵字 `cache` 並執行搜尋。
3. 確認統計結果如下：

   ```text
   TOTAL 7
   VALID 4
   INVALID 3
   INFO 2
   WARN 1
   ERROR 1
   MATCHED 1
   ```

4. 確認空白行不計入 `TOTAL`。
5. 確認欄位數錯誤及 `DEBUG` 等級資料列計入 `INVALID`，且不計入 `INFO`、`WARN` 或 `ERROR`。

### 測試步驟三：空檔案

1. 開啟 `in-3.log`。
2. 確認程式不當機，並顯示：

   ```text
   TOTAL 0
   VALID 0
   INVALID 0
   INFO 0
   WARN 0
   ERROR 0
   ```

### 測試步驟四：查無關鍵字

1. 開啟 `in-4.log`。
2. 輸入關鍵字 `cache` 並執行搜尋。
3. 確認統計結果如下：

   ```text
   TOTAL 5
   VALID 5
   INVALID 0
   INFO 2
   WARN 2
   ERROR 1
   MATCHED 0
   ```

4. 確認內容區域顯示「查無符合條件的日誌」或等義提示。

### 測試步驟五：`.txt` 副檔名

1. 按下「開啟檔案」，選取 `in-5.txt`。
2. 確認程式可以正常開啟 `.txt` 檔案，並在同一個 `RichTextBox` 顯示完整原始日誌內容。
3. 輸入關鍵字 `LOGIN` 並執行搜尋。
4. 確認同一個 `RichTextBox` 改為顯示符合關鍵字的 3 筆日誌。
5. 確認統計結果如下：

   ```text
   TOTAL 6
   VALID 6
   INVALID 0
   INFO 2
   WARN 2
   ERROR 2
   MATCHED 3
   ```

6. 確認 `LOGIN` 與 `login` 的搜尋結果相同。

### 其他操作測試

| 測試情況 | 預期結果 |
|---|---|
| 未選取檔案就按「分析／搜尋」 | 顯示提示，不應當機 |
| 開啟檔案時按取消 | 保留目前畫面，不清除原資料 |
| 關鍵字輸入 `failed` | `in-1.log` 的 `MATCHED` 應為 2；同一列重複出現只計 1 筆 |
| 輸入大小寫不同的關鍵字 | 搜尋結果應相同 |
| 按下「清除」 | 清空檔案內容、關鍵字、搜尋結果與統計數值 |
| 連續開啟不同檔案 | 前一個檔案的統計不得殘留 |

## Problem 4：學習成效分析與成績預測

### 共通測試規則

- 計算過程應保留完整精度，只在輸出時四捨五入至小數點後 2 位。
- `PREDICT` 必須輸出 `Q` 行。
- 輸出不需要單獨的 `REGRESSION` 標題，只輸出 `CORRELATION`、`SLOPE`、`INTERCEPT` 與 `PREDICT`。
- 建議在正式試題中明定：
  - 若 `Sxx = 0` 或 `Syy = 0`，`CORRELATION` 輸出 `0.00`。
  - 若 `Sxx = 0`，`SLOPE` 輸出 `0.00`、`INTERCEPT` 使用平均成績，`PREDICT` 使用平均成績。
